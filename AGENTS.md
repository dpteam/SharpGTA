# SharpGTA: правила работы

## Требования

- Основное ТЗ — `PROMPT.md`; актуальный статус — `docs/ROADMAP.md`. Общаться по-русски.
- Цель: полноценный движок GTA III/VC с нуля на C#, **net40**, Windows XP SP3, без сторонних runtime-библиотек. Win32/D3D9 через P/Invoke и COM допустимы; D3DX и внешние native DLL — нет.
- `net40` — поставка. `net9.0` / `net9.0-windows` — только удобные вторые runtime targets для тех же исходников и тестов. Код остаётся **C# 4**: без `Span`, `MathF`, records, tuples, `HashCode`, default interface methods и новых BCL API.
- Headless — обязательный основной сценарий разработки. Simulation/content core не должен создавать окно, GPU, звук или менять current directory. Null backends не заменяют gameplay streaming.
- Публичный бренд меняется только в `Directory.Build.props`; не разносить `SharpGTA` по UI, assembly metadata или compatibility fingerprints. Внутренние namespace и имена проектов — технические идентификаторы.
- Git не пушить и не делать коммиты/другие mutations без отдельной явной просьбы. Локальное имя уже настроено: `SharpGTA Agent`.

## Данные и референсы

- `refs/` полностью локальный и ignored; оригинальные игровые ресурсы не коммитить и не изменять. Доступны `refs/Grand Theft Auto 3` и `refs/Grand Theft Auto Vice City`; обязательно использовать их в real-asset smoke-тестах. Не выходить за пределы проекта без необходимости и явного контекста пользователя.
- re3/reVC — источники алгоритмов и форматов, не зависимости сборки. Сохранять кредиты и ограничения из `NOTICE.md`/`docs/REFERENCE-SOURCES.md`; не объявлять собственную лицензию без решения владельца.
- DPTDOOM2 — архитектурный образец, не источник для бездумного копирования кода/lockstep. Его GPL-код не переносить без отдельной лицензионной проверки.
- Локальные референсы `re3` и `reVC`: `../reSA/refs/re3` (master, `3233ffe1c4b99e8efb4c41c6794b4fce880cf503`) и `../reSA/refs/reVC` (miami, `a16fcd8d6a79e433c1c6e73d540f1bbe27e14164`). Полный `librw` найден отдельно в `../reSA/refs/librw` (`18532c2e13efbc1aa43f0b00b4459831f9414de0`); vendor-папки внутри re3/reVC пусты.
- Long Term: при unresolved gaps сначала исчерпать re3/reVC/librw, затем статически реверсить `refs/Grand Theft Auto 3/gta3.exe` и `refs/Grand Theft Auto Vice City/gta-vc.exe` по инструкции `docs/REVERSE-ENGINEERING.md`. Не запускать EXE для обычных asset-тестов и не заменять доступные исходники догадками по бинарнику.

## Архитектурные инварианты

- Core не ссылается на III/VC projects. `GameDefinition`, `DataSchema`, limits и game modules описывают различия; не собирать две версии через глобальный `#if VC`.
- **Raw numeric ID существует только внутри выбранного game context.** Не объединять weapon/model/level/opcode enums III и VC по имени или числу. Save/SCM profiles отдельные.
- Порядок DAT directives, simulation modules и побочных эффектов — часть совместимости. Не сортировать их ради удобства.
- Оригинальный `CTimer` variable-step: `timeStep = deltaMs / 1000 * 50`, clamp обычно `0.01..3`. `SimulationClock` — сознательный deterministic 30 Hz driver для headless, не утверждение об оригинальном fixed timestep.
- `GtaRandom` воспроизводит 32-bit PC CodeWarrior LCG, не `System.Random`. Альтернативный re3 `USE_PS2_RAND` — отдельный compatibility profile, если понадобится.
- `CMatrix` rows: Right/Forward/Up/Position. RW `right/up/at` ↔ GTA `right/forward/up` только на render boundary. `System.Numerics` не использовать.
- IMG — streaming с диска по секторам, не `ReadAllBytes` всего образа. Асинхронность позже допустима для I/O, но создание объектов и mutation мира — на simulation thread.
- Бинарные структуры читать field-by-field little-endian с bounds checks, не через `Marshal`/C++ memory image. Текстовые числа — только `InvariantCulture`; asset names — ASCII case-insensitive, GXT keys — ordinal case-sensitive. IPL-поворот: ось кватерниона обязательно нормировать (`RwMatrixRotate` делает это сам, `Quaternion.FromAxisAngle` — нет), иначе повёрнутые объекты получают неверный угол и сжатие по XY.
- `StaticWorld` сейчас только IPL + COLL queries, не полный `CWorld`. Parsed IPL scale сохраняется, но не применяется — как в исходном loader. COLL lines сохраняются, но raycast по ним не ведётся. VC COLL из IMG грузится целиком до первого IPL. Инстансы разложены по оригинальной сетке `CWorld`: 100×100 секторов по 40 units от -2000, main-лист только в middle-секторе bounds, остальные покрытые ячейки — в overlap-листе, дедупликация через scan code; запрос идёт по секторам и сверяется с linear scan (`--verify-sectors`). Bounds-based streaming/eviction самой геометрии ещё нет.
- RenderWare inventory не является DFF/TXD decoder. Layouts брать из `reSA/refs/librw`, GTA integration — из re3/reVC; не выдумывать native formats. Static non-native DFF реализован (`DffReader`, `--dff[-entry]`, полный `--dff-scan`). PC D3D8 TXD/mipmaps и RGBA decode реализованы (`TxdReader`, `TxdPixelDecoder`, `--txd[-entry]`, `--txd-scan`). Skin/HAnim/MatFX binary readers реализованы (`DffPluginReader`, old/split Skin, texture effects); animation/skinning/render behavior ещё нет. IFP читается (`IfpReader`, `--ifp`, `--ifp-animation`): `ANLF`/`ANPK`→`INFO`/`NAME`/`DGAN`/`CPAN`/`ANIM`→`KR00`/`KRT0`/`KRTS`, как `CAnimManager::LoadAnimFile` — сопряжение кватернионов, абсолютные времена в дельты, снятие flips, scale игнорируется; это DTO без сэмплирования по скелету и playback. NATIVE geometry, PAL4/DXT2/DXT4 и PS2-specific decoders остаются отдельными этапами.
- `ZoneWorld`/`PathWorld` — typed data и queries, не полный `CTheZones` simulation или `CPathFind`. Path coords `/16`; attached groups требуют IPL transform, unresolved не выдумывать. VC detached/water paths остаются в исходном порядке. `PathGraph` (ленивый, сбрасывается по `PathWorld.Version`) строит тайл на каждую пару (path-блок, placement), поэтому модель с car- и ped-блоками даёт два тайла на одно размещение и `TileCount` не равен `m_numMapObjects`; узлы — только intern-слоты (`type` 2), связи внутри тайла симметричные по двустороннему предикату `next`, extern-слоты (`type` 1) схлопываются попарно в пределах 1 unit в межтайловые связи, `TryFindNearestNode` считает `|dx|+|dy|+3|dz|` со строгим лимитом. Компоненты связности помечаются как в `CountFloodFillGroups` (обход симметричных связей от первого непосещённого узла, изолированные узлы — отдельные компоненты) и доступны как `PathGraphNode.GroupId`. `--path-merge-distance R` (default 1 — оригинальный порог) пересобирает граф с другим радиусом схлопывания и честно помечает divergence: при 1 unit III сходится в 109 компонент (крупнейшая 1967 из 1971 car-узла), а рост до 10 unit даёт 480 компонент, то есть склеивает чужие линии. У каждой связи есть `LinkDistance` (как `m_distances`) и `LinkCrossesRoad` (`bCrossesRoad`, как в оригинале заполняется только для ped). `TryFindRoute` считает кратчайший маршрут по этим дистанциям (Dijkstra с явной кучей и детерминированным tie-break по индексу узла; оригинал использует bucket queue, поэтому равные по длине варианты могут разрешаться иначе) и честно возвращает false для несвязных узлов. Car-связи дополнительно несут `CCarPathLink`: `LinkDirection` (направление к нижнему индексу узла), `LinkMidpoint`, `LinkLeftLanes`/`LinkRightLanes`; полосы приходят только с extern-переходов, наследуются по узлам с двумя связями (с перестановкой left/right, когда источник указывает обратно на узел) и в конце падают в дефолт 1/1. `PathGraphVerifier` (`--verify-paths`) независимо проверяет симметрию связей, self-links, абсурдные длины, метки компонент и round-trip nearest-node. `trafficLightType` теперь заполняется: game-модули сканируют размещённые светофоры (`GameDefinition.ScanTrafficLights`, III — полоса перед светофором, VC — пересечение оси светофора с парой узлов, четыре модели), `TrafficLights.Mark` ставит тип 1/2 и флаг направления, `Path-Lights:` печатает lights/links/type1/type2/direction, а `PathFollowerModule.ObeyTrafficLights` останавливает машину на стоп-линии в 8 unit перед серединой связи до зелёного (`holds=`). Фазы `LightForCars1/2` воспроизведены точно, но идут по симуляционным миллисекундам, а не по wall-clock `CTimer`; удаление изолированных ped-узлов и spawning/population отсутствуют; detached и attached extern'ы сливаются в одном списке, а не через отдельный `DetachedInfoForTile*`. Dead-end флаги car-узлов реализованы: узел с менее чем двумя живыми соседями помечается, и проход повторяется до стабилизации (`IsDeadEnd`, `CarDeadEndCount`; III 158 из 1971, VC 199 из 2973).
- `EntityPool<T>` воспроизводит `CPool` handle encoding (index<<8 | 7-bit generation, free flag 0x80) и wrap-around allocation; `TimeObjectController` аллоцирует/освобождает IDE `tobj` инстансы по `Runtime.GameClock`, а не по wall clock. Timed-модели фильтруются до draw distance/LOD, поэтому скрытые не запрашиваются у стримера. `WorldEntities` держит пулы оригинальных размеров и раскладывает IPL placements как оригинал: модель из `OBJECT.DAT` → dummy, модель из path-заголовка → treadable, остальные → building (III 5140/5500 + 2336/2802 + 1213/1214, VC 6778/7000 + 2336/2340 + 0/1, `rejected=0`). Object/ped/vehicle пулы наполняются спавном динамики, а не картой. Handles per-pool, как `CPools::Get*Ref`.
- `WorldEntity` — общий base (модель, transform, position, handle, scan code, bounds) для `StaticInstance` и `DynamicEntity`; динамика живёт в том же секторном индексе, что и placements, шагает через `DynamicEntityModule` (`AdvanceDynamic`) и попадает в `ComputeStateHash`. Движение линейное, без физики/коллизий; `PathFollowerModule` ведёт vehicle- и ped-entity вдоль маршрута `PathGraph` с постоянной скоростью (car-узлы для машин, ped-узлы для пешеходов, оба вида в одном модуле), перепланируя маршрут в конце через `RouteSource` (greedy-билдер маршрута предпочитает не заезжать в dead-end узлы; позицию владеет follower, `--spawn-cars N`/`--spawn-peds N` в headless и preview); `DynamicEntityModule` регистрируется один раз на любой набор спавнов. Модель по умолчанию — первый реальный рекорд своего вида: `null`-модель (id 0) пропускается, иначе actor живёт и ходит, но не рисуется, поэтому `Path-Follow` печатает `vehicleModel`/`pedModel`. Машина едет в полосе, а не по линии узлов: `CarLanes` повторяет `LANE_WIDTH = 5` и `CCarPathLink::OneWayLaneOffset`, смещение считается от `LinkDirection` со знаком движения (встречные расходятся по разным сторонам), полоса выбирается стабильно как `handle % lanes` вместо случайной и без перестроений, а на one-way связи против её направления актёр остаётся на линии (оригинал таких не спавнит). `Path-Lanes:` печатает реальные `maxLeft/maxRight/oneWay/multiLane`. Светофоры: `TrafficLights` повторяет обе фазы (`LightForCars1/2`, 16-секундный цикл) и `FindTrafficLightType` (углы 60–150° и 240–330°), `obeyTrafficLights` у follower'а (включён в headless и preview) держит машину на стоп-линии в 8 unit перед серединой связи до зелёного, а `directionFlag == (owner != toNode)` — то же условие «светофор относится к узлу, куда мы едем». `VehicleGap` (6 unit) заменяет отсутствующие коллизии: машина держит зазор до лидера на том же направленном сегменте и в той же полосе, поэтому за светофором образуется очередь; разные полосы и встречные друг друга не видят, а лидер ровно рядом не блокирует (иначе две машины в одной точке заклинились бы). Пешеходные переходы ждут фазу: скан помечает ped-связи с `crossesRoad` флагом `bTrafficLight` (`pedLinks=` в `Path-Lights`), `PhasePeds` даёт 12 с DontWalk / 5 с Walk / 1 с WalkBlink, и пешеход стоит на узле перед переходом до ровной Walk, но не замирает посреди дороги (III 402 помеченных перехода, VC 20). `CharacterMoveModule` — первый игрокоподобный модуль: `InputFrame` → скорость, `StaticWorld.QueryRay` по COLL (мировой луч, локальный внутри инстанса) + три зонда на высоте груди дают упор в стену и скольжение, а вертикаль повторяет `CPhysical::ApplyGravity` (`GRAVITY = 0.008`, скорость в единицах 50 Гц, `IsGrounded`: шаг с края — настоящее падение, а не телепорт вниз; `--walk X Y Z DX DY SPEED`, в preview `--play` с камерой третьего лица); тело — два кольца по три луча (0.45 и грудь 1.0), поэтому бордюр ниже 0.45 перешагивается, а всё выше блокирует; другие актёры — цилиндры (`ActorLimit`, 0.4 пед / 1.2 машина), и столкновение одностороннее: пешеход упирается, но не толкает; это не `CPhysical` — наклон круче ~45° читается как стена, нет транспорта как тела и swept-объёма. Ped DFF в III — два clump'а (тело и голова), их конвертирует `RenderResourceManager.GetModel` вместе с `DffFrameTransforms.ResolveAll`; `GetClump` остаётся только для одноclump'овых static-моделей. `VehicleGroundProbe`/`Path-Follow-Ground` меряет, не висят ли машины над дорогой, и D3D9 preview умеет рисовать заспавненные entities (`--spawn N`), используя те же streamed model/TXD slots. `TrafficPopulationModule` замыкает жизненный цикл: с `--recycle` follower отдаёт закончившего маршрут actor'а (`RecycleVehicles`/`RecyclePeds`, `TryTakeRetired`), модуль деспавнит его из мира и спавнит замену на следующем узле-кандидате (детерминированный round-robin со stride, не random-по-зонам как `CPopulation`), адоптируя уже заспавненных actors через `CountOf`; население остаётся на target, а `Path-Traffic` печатает live/target и spawned/despawned/recycled. В D3D9 preview тот же модуль работает с anchor = preview spawn и `ViewRadius`, а `RouteHops` снижен до 6 (`PreviewRecycleHops`), потому что 40-hop маршрут в III — это ~2800 unit и за короткий прогон ни один actor не успел бы закончить.
- `Rendering/` содержит managed mesh/material/texture DTO, `DffFrameTransforms`/`DffRenderSceneBuilder`, bounded `StaticWorldScene` с model draw distance/LOD handoff, presentation-only `FreeFlyCamera` и `NullRenderDevice`; никаких Win32/D3D imports в Core. `AtomicFrameIndex` сохраняется, `local * parent` для static non-skinned frames обязателен. `Assets/StreamingPool` — синхронные slot states/refcount/priority/LRU с loader/unloader delegates, без GPU. `IO/AsyncByteCache` — два background byte-канала с bounded LRU-бюджетом; worker'ы только читают bytes, decode и mutation мира остаются на simulation thread. `--render-preview` проверяет resources без GPU, но не является изображением или полным renderer.
- `src/SharpGTA.D3D9` — отдельный Win32/D3D9 proof-of-concept без зависимости Headless от него: direct vtable `StdCall`, fixed-function triangle/UI quads, static 3D meshes через managed-pool vertex/index buffers с оригинальными shared vertices/indices и `DrawIndexedPrimitive`, managed A8R8G8B8 textures, directional light + D24S8, lockable back-buffer readback/BMP до `Present` и explicit `Reset`. `--model NAME` открывает static DFF model preview с orbit camera; `--world` и `New Game → Yes` — III static IPL world preview с free-fly camera, COLL query, sector-list candidates (`--verify-sectors`), `--path-overlay` для line-list отрисовки рёбер `PathGraph` (car/ped/water цвета) и `--path-route X Y Z X2 Y2 Z2` для отрисовки найденного маршрута поверх мира, `--spawn-cars N [--spawn-car-speed S]` для машин и `--spawn-peds N [--spawn-ped-speed S]` для пешеходов, едущих/идущих по сети через общий `PathFollowerModule`, `--recycle` для замены закончивших маршрут актёров рядом с камерой (короткие маршруты, `PreviewRecycleHops`), `--play` для третьего лица: один пед под управлением WASD, орбитальная камера за спиной с укорачиванием выноса по `QueryRay`, `--spawn N` для динамических objects, и streamed model/TXD slots (states/refcount/priority/sync load/LRU/Deferred, default capacities 512/96, `--stream-budget`/`--txd-budget`). Model draw distance (damage-aware) и suffix LOD handoff работают; DFF/TXD bytes доставляются через `IO/AsyncByteCache` (2 worker, byte LRU, `--byte-budget` MiB), decode и все mutations — на simulation thread; timed `tobj` видимость идёт по `Runtime.GameClock` (`--time H`), динамика шагает `DynamicEntityModule`; dynamic entity LOD, физика и gameplay behavior (peds/vehicles) отсутствуют. World material сначала использует IDE TXD своей модели (`GTA3.IMG`, затем `TXD.IMG`, затем loose), и только потом persistent loose `GENERIC.TXD` fallback; managed/GPU caches ключуются `(IDE TXD, texture name)`, не одним texture name. `TXD.IMG` читается по секторам и закрывается при `Dispose`; unresolved LOD material references сообщаются, чужие TXD не подставляются. Shaders/state cache и полное device-loss recovery ещё впереди. Managed ABI/layout/BMP tests не создают окно/GPU.
- `src/SharpGTA.Launcher` — standalone WinForms/MSHTML launcher (не WebView2), embedded ES5 HTML/CSS и bridge через отменяемую `sharpgta://` навигацию. Не использовать `window.external` как обязательный механизм; никаких CDN/HTTP server/внешних DLL. Launcher запускает D3D9 напрямую и хранит общие frontend settings; оригинальные деревья не изменяет. Для тестов есть изолированные `SHARPGTA_LAUNCHER_*` variables, не включать их в обычный запуск.
- GTA III interactive frontend использует `src/SharpGTA.Core/Frontend` для state/layout/GXT/font metrics и `SharpGTA.D3D9` для textures/glyphs/input. `SharpGTA.Presentation/FrontendPreferencesState` общий для launcher/menu; не делать расходящиеся дубликаты сериализации. VC frontend пока не реализован, не подменять его III assets. Gameplay bootstrap/save profiles пока не подключены; `New Game → Yes` означает только явно названный static world preview, не запуск simulation/gameplay.
- Отсутствующие оригинальные ресурсы не должны ломать synthetic tests. Для real-asset checks честно сообщать `SKIP/NOT RUN`, не выдавать за успех.
